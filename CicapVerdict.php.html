27/**
28 * The verified mode for the c-icap `virus_scan` service with ClamAV (c-icap 0.6.3, c-icap-modules 0.5.7, ClamAV 1.4.3;
29 * docs/cicap-clamav.md): it reads an answer of that service as the service means it, and an answer that does not show
30 * that the file was scanned is an error, never a clean result. Pass it to {@see IcapClient} to turn the mode on.
31 *
32 * It is made for one service, given as the path and query a scan names it by (`/avscan`): the client scans with no other
33 * service while the mode is on, and takes the endpoint from the {@see Config}. The service has to be set up as the
34 * reference service is: the answers cannot show whether it scans every type of file.
35 *
36 *  - Infection: `X-Infection-Found: Type=n; Resolution=n; Threat=name;` and `X-Violations-Found: count - name
37 *    problem-id resolution-id ...` (folded over several lines), read by value and count, whatever the spelling of the
38 *    names and whatever the header list of the {@see Config}. The result names the threat, not the text of the header.
39 *    A 200 or 206 with an infection is a finding, also as the answer to a preview. Headers that contradict each other
40 *    or a 204, or that are malformed, are an error, and so is a 100 Continue that carries any of that.
41 *  - Not scanned: ClamAV reports a file over its limits (`AlertExceedsMax`) and an encrypted archive or document
42 *    (`AlertEncrypted`) with a name of its own, `Heuristics.Limits.Exceeded...` and `Heuristics.Encrypted...`. That says
43 *    that the file was not looked into: an error, not a finding. Every other name is a finding.
44 *  - Clean: only a 204 to a file that was sent whole (the preview held all of it, or the service asked for the rest with
45 *    100 Continue). For a type it does not scan the service answers the preview of a file that is not all sent with a
46 *    204 at once, so that is an error, and so is a 200 or 206 without an infection (the message sent back, a block or
47 *    error page).
48 *
49 * What an answer cannot show is whether the service scans everything it is sent: a service that skips a type also
50 * answers a file that the preview holds, and sometimes a file sent without a preview, with the same 204 as for a clean
51 * scan. That is for the configuration of the service.
